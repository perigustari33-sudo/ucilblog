Image Builder vs Build dari Sumber: Kenapa opkg Jadi Penentu

Pengalaman Saya

Saya punya router TP-Link MR3420 v2 dengan Flash 8MB. Saya ingin firmware OpenWrt 18.06.9 yang lengkap: LuCI, driver USB, driver modem 3G/4G, dan semua paket yang saya butuhkan.

Saya coba dua pendekatan:

  1. Image Builder resmi (target ar71xx/tiny, profile tl-mr3420-v2)
  2. Build dari sumber (buildroot)

Hasilnya menarik:

  • Image Builder → gagal karena firmware kelebihan 148.123 byte dari kapasitas Flash
  • Build dari sumber → berhasil, firmware jalan
  • Tapi setelah firmware jalan, opkg dari repo resmi sering error

Kenapa bisa begitu? Ternyata bukan soal firmware-nya, tapi soal kernel hash.

Kunci Masalahnya: Kernel Hash

Di repo OpenWrt, kernel module (kmod-*) disimpan dalam folder dengan nama seperti ini:

.../targets/ar71xx/tiny/kmods/4.9.243-1-db2d5425c674d1648616e3c37760e80e/

Bagian db2d5425c674d1648616e3c37760e80e itu adalah hash dari konfigurasi kernel yang dipakai buildbot resmi. Setiap perubahan kecil di .config kernel akan menghasilkan hash berbeda.

opkg memverifikasi ini lewat metadata:

Kernel-Version: 4.9.243-1-db2d5425c674d1648616e3c37760e80e

Kalau uname -r di router Anda tidak persis sama dengan string itu, opkg akan menolak dengan error:

Packages for kmod-xxx found, but incompatible with the architectures configured

Mengapa Image Builder Harus Tetap Dipakai

1. Kernel Hash Sama dengan Repo Resmi

Image Builder resmi dibangun dari buildbot yang sama dengan repo paket. Artinya:

Image Builder Build dari Sumber
Kernel hash db2d5425c674d1648616e3c37760e80e Hash berbeda
Kmod dari repo ✅ Cocok ❌ Tidak cocok
opkg update ✅ Jalan ❌ Sering gagal
opkg install kmod-* ✅ Bisa ❌ Tidak bisa

Jadi kalau Anda mau bisa opkg install dari repo resmi, Image Builder adalah satu-satunya cara.

2. opkg Adalah Nyawa OpenWrt

OpenWrt tanpa opkg seperti Android tanpa Play Store. Anda tidak bisa:

  • Install paket baru
  • Update keamanan
  • Tambah fitur tanpa build ulang
  • Install driver USB/modem yang tidak masuk firmware awal

Kalau opkg mati, setiap perubahan sekecil apapun berarti build ulang firmware — dan itu 1-2 jam per build.

3. Image Builder Dirancang untuk Ini

Image Builder secara desain:

  • Menyertakan kernel image yang sudah jadi (bukan source)
  • Mengambil kmod dari feed online yang sudah cocok
  • Tidak membangun apa pun dari source

Commit OpenWrt bahkan secara eksplisit menyebutkan:

"We don't ship the kernel sources, so using the base git as a feed will fail when trying to build kernel modules with separate install steps. Instead of trying to fixup the install steps, let's just skip building kernel modules altogether."

Artinya: Image Builder sengaja tidak build kmod karena memang tidak punya kernel source. Kmod yang dipakai adalah yang sudah jadi dari repo.

Mengapa Build dari Sumber Berisiko opkg Tidak Cocok

1. Kernel Hash Berbeda

Build dari sumber menghasilkan kernel dengan hash yang berbeda dari buildbot resmi. Penyebabnya:

  • Konfigurasi kernel yang berbeda
  • Versi toolchain yang berbeda
  • Patch yang berbeda
  • Environment build yang berbeda

Hash ini sangat sensitif — perubahan sekecil apapun di .config kernel akan mengubahnya.

2. Kmod dari Repo Tidak Bisa Dipakai

Karena hash beda, kmod dari repo tidak akan pernah cocok dengan kernel Anda. Anda harus:

  • Build kmod sendiri dari source yang sama
  • Atau selesaikan semua di buildroot — jangan pernah opkg install kmod-*

3. Konsekuensinya

Ingin Cara
opkg jalan Build dari sumber → build kmod sendiri → buat repo lokal sendiri
Cepat & simpel Image Builder resmi
Kontrol penuh + opkg jalan Kompleks, perlu maintain repo sendiri

Trade-Off yang Harus Dipilih

Aspek Image Builder Build dari Sumber
Kontrol paket Terbatas Penuh
Ukuran firmware Terbatas (4MB target tiny sering gagal) Bisa dioptimasi
Kernel hash Sama dengan repo Berbeda
opkg dari repo resmi ✅ Jalan ❌ Gagal
Update paket Mudah via opkg Harus build ulang
Waktu build ~10 menit ~1-2 jam
Reproducibility Tinggi Tergantung environment

Kesimpulan

Kalau Anda ingin tetap bisa opkg update dan opkg install dari repo resmi, pakai Image Builder. Itu satu-satunya cara yang dijamin berhasil karena kernel hash-nya sama dengan repo.

Kalau Anda build dari sumber, terima kenyataan bahwa opkg dari repo resmi tidak akan cocok. Anda harus build semua paket yang Anda butuhkan langsung ke dalam firmware, dan tidak bisa install paket baru setelahnya.

Untuk MR3420 v2 dengan Flash 8MB, pilihan terbaik adalah:

  1. Image Builder target generic — sudah menyertakan LuCI, banyak ruang, kernel hash sama dengan repo
  2. Build dari sumber — kalau Image Builder gagal karena ukuran, tapi terima konsekuensi opkg mati

Jangan campur keduanya. Build dari sumber + opkg dari repo resmi = kombinasi yang paling sering error.
